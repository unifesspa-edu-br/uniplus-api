Pre-requisito obrigatório 1 — provisionamento externo de Secret:
  Este chart espera que um Kubernetes Secret com o nome
    {{ .Release.Name }}-portal-secrets
  já exista no namespace {{ .Release.Namespace }} antes do `helm install`.
  O Deployment monta o Secret via envFrom (templates/deployment.yaml:33-34) —
  sem o Secret pré-existente, os pods do Portal falham com
  "secret not found" e nunca atingem o estado Ready.

  O Secret deve conter as seguintes chaves (.NET ConfigurationProvider
  resolve cada uma como variável de ambiente equivalente):

    ConnectionStrings__PortalDb     # Host=...;Database=uniplus_portal;Username=...;Password=...
    Redis__ConnectionString         # host:port
    Kafka__BootstrapServers         # host1:9092,host2:9092
    Storage__Endpoint               # MinIO/S3 endpoint
    Storage__AccessKey
    Storage__SecretKey
    Auth__Authority                 # https://<keycloak>/realms/unifesspa

Pre-requisito obrigatório 2 — configuração de CORS:
  Em produção (ASPNETCORE_ENVIRONMENT=Production, default deste chart),
  Program.cs invoca AddCorsConfiguration(...).ValidateOnStart() — o app
  recusa subir com Cors:AllowedOrigins vazio. Defina pelo menos uma
  origem confiável em values.yaml (`cors.allowedOrigins`) — o ConfigMap
  renderiza cada entrada como Cors__AllowedOrigins__<i>. Exemplo:

    cors:
      allowedOrigins:
        - https://portal.unifesspa.edu.br
        - https://uniplus.unifesspa.edu.br

  Sem essa configuração, os pods crashloopam no startup com
  OptionsValidationException. Os charts uniplus-selecao e uniplus-ingresso
  seguem o mesmo contrato (`cors.allowedOrigins`).

Pre-requisito obrigatorio 3 — redes confiaveis do proxy:
  A aplicacao roda atras de um proxy que termina o TLS, e so honra o
  X-Forwarded-Proto vindo das redes declaradas. Fora de Development,
  AddReverseProxyConfiguration(...).ValidateOnStart() recusa subir com
  ReverseProxy:TrustedNetworks vazio. Declare a rede de onde o proxy
  alcanca o pod em values.yaml (`reverseProxy.trustedNetworks`) — o
  ConfigMap renderiza cada entrada como ReverseProxy__TrustedNetworks__<i>.
  Exemplo:

    reverseProxy:
      trustedNetworks:
        - 10.42.0.0/16

  Sem essa configuracao os pods crashloopam no startup, pelo mesmo
  OptionsValidationException do CORS. Com a lista vazia aceita, o efeito
  seria pior e silencioso: o app subiria enxergando http atras do TLS e
  emitiria Link e Location apontando para endereco sem TLS.

  Estratégia recomendada de provisionamento:
    - PROD/HML: External Secrets Operator (ESO) sincronizando do HashiCorp
      Vault. A integração ESO/Vault é responsabilidade da Story de stand-up
      do Vault (cross-charts). Até lá, criar o Secret manualmente com
      `kubectl create secret generic {{ .Release.Name }}-portal-secrets
      --from-literal=...`.
    - Dev local: usar `docker compose -f docker/docker-compose.yml
      -f docker/docker-compose.override.yml` em vez do chart Helm — o
      compose já injeta as variáveis correspondentes (porta 5302).

Pre-requisito 4 — origens da pagina publica do certame:
  A rota GET /api/portal/certames/{identificador} compoe o contrato publico de
  Selecao com a consulta de atos de Publicacoes, ambos no deployable
  monolitico. Os enderecos (`origens.selecaoBaseUrl` e
  `origens.publicacoesBaseUrl`) sao obrigatorios e validados na subida: sem
  eles, ou com endereco invalido, o pod crashloopa com
  OptionsValidationException. O padrao aponta para o Service do chart
  infra/helm/uniplus com o release "uniplus"; ajuste ao nome real do release
  do monolito:

    origens:
      selecaoBaseUrl: http://<release-do-monolito>-uniplus-api
      publicacoesBaseUrl: http://<release-do-monolito>-uniplus-api

Endpoints expostos pela API após o pod ficar Ready:
  GET /health/live               -> liveness (dependency-free, sempre 200 enquanto vivo)
  GET /health                    -> readiness (agregado: OIDC, Postgres, Kafka, Redis)
  GET /api/portal/ping           -> endpoint dummy para validar OpenAPI
  GET /api/portal/certames/{identificador} -> pagina publica do certame (anonima)
  GET /openapi/portal.json       -> documento OpenAPI 3.1
  GET /api/auth/me               -> claims do token (autenticado)
  GET /api/profile/me            -> perfil consolidado (autenticado)
