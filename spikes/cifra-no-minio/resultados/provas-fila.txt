==================== Alternativa sem cópia: o arquivo aprovado ganha uma etiqueta no próprio bucket de envio ====================

# A credencial api-etiqueta só lê do bucket de envio o objeto com a etiqueta verificacao=aprovado.

$ cat ./config/politica-api-etiqueta.json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AssinaOEnvio",
      "Effect": "Allow",
      "Action": ["s3:PutObject"],
      "Resource": ["arn:aws:s3:::uniplus-envios/*"]
    },
    {
      "Sid": "AssinaALeituraSoDoArquivoAprovado",
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": ["arn:aws:s3:::uniplus-envios/*"],
      "Condition": {"StringEquals": {"s3:ExistingObjectTag/verificacao": "aprovado"}}
    }
  ]
}

# 1. O candidato tenta se aprovar: acrescenta x-amz-tagging ao PUT pela URL pré-assinada.

$ curl -T um-mb.pdf -H "x-amz-tagging: verificacao=aprovado" <URL de envio>
HTTP 200

$ mc_admin tag list local/uniplus-envios/176a447b57a4437685c7e3c9db2dd24a
Name        : http://localhost:9000/uniplus-envios/176a447b57a4437685c7e3c9db2dd24a
verificacao : aprovado

# 2. Sem a etiqueta, a URL de leitura assinada pela api-etiqueta é recusada.
GET pela URL assinada com a credencial api-etiqueta: HTTP 403

# 3. Com a etiqueta posta pelo verificador, a mesma leitura passa.
GET pela URL assinada com a credencial api-etiqueta: HTTP 200

# 4. Se o candidato regravar o objeto pela mesma URL, a etiqueta não sobrevive: a leitura volta a ser recusada.

$ mc_admin tag list local/uniplus-envios/176a447b57a4437685c7e3c9db2dd24a
